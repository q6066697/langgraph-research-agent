## 2026-07-29 — Упаковка агента в HTTP-сервис и Docker

**Цель:** превратить консольный ReAct-агент в развёртываемый веб-сервис —
закрыть пробел «упаковка AI-агента в прод» (Docker, готовность к деплою).

### Что сделано

- **`api.py` — сервис на FastAPI.** Обернул граф агента в HTTP-интерфейс,
  не трогая его логику. Два эндпоинта:
  - `GET /health` — проверка живости (liveness probe), возвращает `{"status": "ok"}`;
  - `POST /chat` — принимает `{"question": "..."}`, прогоняет через `graph.invoke`,
    возвращает `{"answer": "..."}`. Вход валидируется через Pydantic-модели,
    ошибки агента отдаются как `502` вместо голого стектрейса.
- **Проверка локально.** Запустил через `uvicorn`, протестировал оба эндпоинта
  в авто-документации Swagger (`/docs`). Агент реально сходил в веб через Tavily
  и вернул ответ с источниками.
- **`Dockerfile` — multi-stage сборка.** Зависимости ставятся в отдельном
  build-слое, в финальный slim-образ переносится только нужное. Запуск под
  non-root пользователем. API-ключи передаются в рантайме через `--env-file`
  и не зашиваются внутрь образа.
- **`.dockerignore`.** Исключил из образа мусор и — критично — `.env` с ключами.
- **Проверка в контейнере.** Собрал образ, запустил, протестировал `/chat` —
  агент работает уже внутри Docker.
- **Git-гигиена.** Отдельная feature-ветка, `.venv/` и `.idea/` в `.gitignore`,
  коммиты по Conventional Commits, обновлённый README (раздел про запуск сервиса
  и Docker), слияние в `master` через Pull Request с последующей чисткой веток.

### С чем столкнулся и как решил

- **PowerShell — не bash.** Команды с `&&` и `printf` не работают; перешёл на
  синтаксис PowerShell (`Add-Content`, `;` как разделитель команд).
- **Баг консоли (PSReadLine).** При вставке длинного многострочного блока (код
  `api.py`) консоль ломала отрисовку и роняла ввод. Вывод: длинные файлы не
  вставлять в терминал, а создавать через Claude Code или блокнот.
- **Недостающая зависимость.** Сервис падал при старте: `agent.py` импортировал
  `langfuse` (из предыдущей сессии с трейсингом), но пакета не было в
  `requirements.txt`. Для Docker это критично — образ бы тоже не собрался.
  Дописал и установил `langfuse`.
- **Docker-движок не запущен.** Сборка выдала ошибку про pipe — Docker Desktop
  был выключен. Запустил, дождался статуса Running, повторил сборку.
- **Рассинхрон репозитория.** Правка README про сервис уехала на GitHub в
  `master` напрямую, а ветка с кодом (`api.py`, `Dockerfile`) на сервер не
  попала. В итоге `master` описывал сервис, файлов которого в нём не было —
  для любого, кто склонировал бы репозиторий, проект был бы нерабочим. Вдобавок
  локальный git отстал от сервера на три коммита и не знал про них.
  Разрулил по шагам: `git fetch` → `rebase` своих коммитов поверх свежего
  `master` → `push` → Pull Request → merge. Rebase прошёл без конфликтов,
  потому что мои правки и изменения на `master` затрагивали разные участки файлов.

### Итог

`master` в согласованном состоянии: любой может склонировать репозиторий, собрать
образ одной командой и получить рабочий сервис. Агент запускается и локально
(`uvicorn`), и в Docker.
